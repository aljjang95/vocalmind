## Executive Summary

현재 앱은 빌드와 테스트는 통과하지만, 실사용 관점에서는 "공개 체험"과 "수업 핵심 기능" 사이에 마찰이 큽니다. 특히 공개 레슨 페이지에서 TTS가 비로그인 401로 실패하고, 시범 음원 도메인 일부가 해석되지 않으며, 백엔드 WebSocket 미기동 시 핵심 연습이 즉시 오류로 멈춥니다. 또한 전 페이지 공통으로 CSP nonce hydration mismatch가 발생해 Next 개발 오버레이가 계속 떠 있습니다.

P0 치명 중단은 확인되지 않았습니다. 다만 P1급 문제는 즉시 수정하는 편이 좋습니다. "무료로 시작"이라고 말하는 랜딩과 실제로는 로그인 벽 뒤에 있는 무료 상담/AI 코치/커뮤니티/스튜디오의 체감이 어긋나고, 데모 페이지의 문구 오염은 서비스 신뢰도를 바로 깎습니다.

## P0

현재 점검 범위에서 P0는 발견하지 못했습니다.

단, 인증된 실제 계정으로 코치 채팅, 결제 위젯, 업로드, 스튜디오 작업 생성까지 연결된 상태는 이번 세션에서 확인하지 못했습니다. 현재 브라우저 세션은 비로그인 상태였고, 인증 필요 기능은 로그인 요구 UX까지 검증했습니다.

## P1

### P1-1. 전 페이지 CSP nonce hydration mismatch

- 화면/경로: `/`, `/pricing`, `/journey`, `/journey/1`, `/scale-practice/1`, `/auth/login`
- 재현 단계:
  1. `http://localhost:3010/` 접속
  2. 콘솔과 Next DevTools issue badge 확인
- 기대 동작: hydration mismatch 없이 렌더링되고 콘솔에 신규 React hydration error가 없어야 한다.
- 실제 동작: `Script id="__nonce_carrier"`의 `nonce`가 서버 렌더와 클라이언트에서 달라 React hydration mismatch가 반복 발생한다.
- 원인 추정:
  - `app/layout.tsx`에서 `headers().get('x-nonce')`를 읽어 `next/script`에 주입한다.
  - 클라이언트 hydration 시 해당 nonce 속성이 빈 값으로 비교되어 불일치한다.
  - 관련 위치: `app/layout.tsx:13-38`, `proxy.ts:10-35`
- 수정 제안:
  - `__nonce_carrier` 스크립트 제거 가능 여부를 먼저 검증한다.
  - 필요하다면 Next 16의 CSP nonce 권장 패턴으로 전환하고, 임의 carrier script 대신 response header 기반 nonce와 framework script nonce가 같은 경로로 흐르게 한다.
  - 수정 후 `npm run dev`에서 `/`, `/journey/1`, `/scale-practice/1` 콘솔 hydration error가 사라지는지 확인한다.

### P1-2. 공개 레슨의 TTS 버튼이 비로그인에서 401로 실패

- 화면/경로: `/journey/1`
- 재현 단계:
  1. 비로그인 상태로 `/journey/1` 접속
  2. `음성으로 듣기` 클릭
- 기대 동작: 공개 레슨이면 TTS가 재생되거나, 비로그인 제한이 있으면 버튼 자체가 잠기고 로그인 안내가 보여야 한다.
- 실제 동작: 콘솔에 `POST /api/tts 401 Unauthorized`가 발생한다. 화면에는 실패 이유가 명확히 드러나지 않고 "음성 파일을 불러올 수 없어 TTS로 재생합니다" 문구가 남는다.
- 원인 추정:
  - `/journey/*`는 `PUBLIC_PATHS`로 공개되어 있다.
  - `/api/tts`는 `supabase.auth.getUser()`를 강제한다.
  - 관련 위치: `proxy.ts:5`, `app/api/tts/route.ts:6-11`, `lib/hooks/useTTS.ts:67-68`
- 수정 제안:
  - 공개 레슨용 TTS는 짧은 텍스트에 한해 비로그인 허용 + rate limit로 보호한다.
  - 또는 공개 페이지에서는 미리 생성된 오디오만 사용하고 TTS 버튼을 로그인 CTA로 바꾼다.
  - 오류 발생 시 toast 또는 inline alert로 "로그인 후 음성 듣기 가능"을 명확히 보여준다.

### P1-4. 핵심 실습이 백엔드 WebSocket 미기동 시 바로 막힘

  - `scripts/dev.sh`와 Windows용 dev script를 정리해 프론트/백엔드 동시 실행을 기본 경로로 만든다.

## Product Leverage

### 1. "무료 상담"을 로그인 전 체험 가능하게 만들기

랜딩은 "카드 등록 없이 무료"를 강하게 약속하지만 실제 CTA는 바로 로그인입니다. 첫 녹음 30초까지는 게스트 세션으로 열고, 분석 결과 저장/로드맵 상세/AI 코치 연결 시점에 회원가입을 요구하면 전환율이 좋아질 가능성이 큽니다.

권장 구조:
- 게스트 `session_id` 발급
- 30초 녹음 + 4축 preview 분석
- 결과 상단 30%, 상세 로드맵/저장/공유는 signup wall
- 회원가입 후 guest result를 user profile에 merge

### 2. 핵심 수업은 "백엔드 준비 상태"를 제품 UI로 흡수하기

현재는 서버가 죽어 있으면 사용자가 마이크를 누른 뒤 실패를 배웁니다. 보컬 앱은 마이크 권한, 브라우저 정책, 백엔드 상태, 오디오 포맷 실패가 잦으므로 수업 진입 전 "준비 체크"가 필요합니다.

권장 구조:
- lesson preflight: backend health, microphone permission, browser support, websocket reachability
- 실패 시: demo mode, guide video, retry, support link
- 성공 시: 바로 녹음 시작

### 3. 공개 커뮤니티/스튜디오 preview를 만들기

커뮤니티와 스튜디오는 서비스 매력을 보여주는 영역인데 현재 비로그인에서는 로그인 벽입니다. "둘러보기"는 공개, "작성/투표/구매/업로드"는 인증으로 나누면 사용자가 가입 전에 가치를 이해할 수 있습니다.

### 4. 콘텐츠 자산을 코드 상수에서 manifest + 검증으로 이동하기

YouTube, Supabase 오디오, 시범 음원은 제품의 수업 품질 그 자체입니다. 코드 상수에 고정하면 도메인 만료/권한 변경/URL 변경이 배포 전까지 드러나기 어렵습니다.

권장 구조:
- `lesson_assets` manifest
- CI에서 HEAD/metadata 검증
- 관리자 화면에서 broken asset 표시
- 수업 페이지는 asset status에 따라 버튼 노출/폴백 결정
