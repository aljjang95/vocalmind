## 남은 리스크

### R1. `PUBLIC_BACKEND_URL`은 로컬에서 아직 미설정

- 현재 `/health`는 `PUBLIC_BACKEND_URL` 하나 때문에 `degraded`입니다.
- 이유: Modal 원격 워커가 콜백할 공개 FastAPI URL이 로컬 PC에는 기본적으로 없습니다.
- 코드 버그라기보다 운영/env 구성 리스크입니다.
- 실제 Studio job end-to-end를 로컬에서 검증하려면 ngrok/Cloudflare Tunnel 같은 공개 URL을 열고 `PUBLIC_BACKEND_URL`에 지정해야 합니다.

### R2. 로그인 사용자 기준 결제/업로드/스튜디오 생성은 실제 세션 필요

- 비로그인 상태에서는 보호 리다이렉트 UX까지 확인했습니다.
- 실제 Supabase 로그인 쿠키 또는 테스트 계정이 있는 상태에서 `/studio/new`, `/credits`, `/community`, `/coach`의 쓰기 플로우를 한 번 더 검증해야 합니다.
- 실결제/외부 발송은 테스트 키 또는 별도 승인 없이 호출하지 않는 것이 맞습니다.
