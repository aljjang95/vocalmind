## 발견

### 🟢 P2 — 문서 stale: middleware.ts → proxy.ts (Next 16 컨벤션)
- 위치: `next.config.js:6,8,24` 주석 + `CLAUDE.md` Architecture (`middleware.ts` 언급)
- 실제: Next.js **16.2.6**는 미들웨어 파일명이 `proxy.ts`. 현 `proxy.ts`가 정상 동작
  (프로덕션 `/studio` → `/auth/login?...login_required` 리다이렉트 + CSP 헤더 실측으로 동작 확인).
- 영향: 코드 버그 아님. 신규 기여자 혼란 가능. 주석/문서만 갱신 필요.

### 🟡 P1 — CSP prod `script-src 'unsafe-eval'` 잔존
- 위치: `proxy.ts:19` (prod scriptSrc)
- 실측 헤더: `script-src 'self' 'nonce-...' 'strict-dynamic' 'unsafe-eval' https://www.youtube.com blob:`
- 분석: nonce+strict-dynamic으로 인라인 XSS는 차단되나, CSP3 스펙상 strict-dynamic이
  있어도 `'unsafe-eval'`은 무시되지 않음 → eval()/Function() 공격 표면 잔존.
- 소스 직접 grep: 프론트 번들에 직접 eval/new Function/WASM 사용 0건
  (modal_app Python 워커 3개만 — JS 무관). unsafe-eval 필요성은 node_modules 런타임 의존.
- 권고: prod에서 `'unsafe-eval'` → `'wasm-unsafe-eval'`(WASM만 허용) 시도 후
  피아노/피치/녹음 분석 기능 브라우저 회귀 검증. 깨지면 롤백. **회귀 위험 큰 변경, 단독 신중.**

### 🟢 P2 — CSP `connect-src wss://*` 와일드카드
- 위치: `proxy.ts:22` (prod connectSrc)
- 분석: 모든 wss 도메인 허용 → XSS 결합 시 임의 wss exfil 채널.
- 실제 wss 연결 대상 (코드 확인):
  - 백엔드 WS: `wss://*.fly.dev` (`useRealtimeEval`/`useRhythmDetection`/`useScaleWebSocket` → `/ws/evaluate`,`/ws/rhythm`,`/ws/scale-practice`)
  - Supabase Realtime: `wss://*.supabase.co` (`useStudioJob`)
- 권고(안전): `wss://*` → `wss://*.fly.dev wss://*.supabase.co`. 기능 유지 + 와일드카드 제거.
  단 실습 페이지 WS 연결 회귀 검증 필요.
